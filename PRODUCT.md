## Platform

web

## Stack

Next.js + TypeScript (explicitly specified by the user for Phase 15). No image-generation tool is available in this environment, so the build path is code-first.

## Users

Researchers, graduate students, and academics doing literature review from a single seed paper: someone who has just found (or written) one paper and needs to place it in its surrounding literature, see what has already been done, and find a legitimate, evidence-backed gap to work on next. They bring their own LLM provider API key (BYOK) -- a technically comfortable audience, not a general consumer one.

## Product Purpose

ResearchNexus takes one seed paper through profile extraction, multi-strategy discovery of related work, transparent multi-signal ranking, typed relationship trail-building, a persistent multi-paper workspace, evidence-grounded RAG chat, comparison tables, structured research-gap detection, and next-step research directions -- each stage's output usable on its own, each stage feeding the next. Success is a researcher going from "I have this one paper" to "here is a specific, evidence-backed gap I could work on" without ever being shown a claim, citation, or relevance score the system cannot point to real supporting text for.

## Positioning

Every existing "AI research assistant" (including the IEEE BigData 2024 system this project directly benchmarks against) generates free-text literature-review prose with no auditable trail back to source text, invented reference strings, unlabeled relevance scores, and no structural distinction between "these papers are similar" and "this paper extends / contradicts / competes with that one." ResearchNexus's mechanism: every ranked result shows its real per-signal scores (never a fabricated percentage); every discovered relationship is one of 7 typed categories with a fired rule and a verbatim evidence span; every chat answer, gap, and direction traces to a real source span or is not shown; every reference string is built by a deterministic formatter, never generated by the LLM; the LLM's role is constrained to phrasing and hypothesis generation, never fact invention, and every LLM-touched claim carries a visible confidence band, never an invented percentage.

## Operating Context

Core session shape: upload or select a seed paper, the system extracts a structured research profile (problem, methods, datasets, findings, limitations), the researcher reviews it, the system discovers related papers via several parallel strategies, results carry per-signal scores and plain-language reasons, the researcher reviews the typed research trail (similar / foundational / competing / method-extension / dataset-related / contradictory / recent) and accepts or rejects edges, selected papers form a persistent workspace. From the workspace the researcher can ask evidence-grounded questions (RAG chat with inline hover-citations), build a comparison table, generate research gaps (each needing at least two supporting papers and a passed self-support check), turn an accepted gap into a concrete research direction, and export citations. A per-workspace research graph and an activity/tool-call log exist as an inspectable trace of what the system actually did. Every generative action requires the researcher's own LLM key (BYOK); deterministic operations (citation formatting) never need one. All work is workspace-scoped and tenant-isolated per user.

## Capabilities and Constraints

- BYOK only: no ResearchNexus-hosted LLM access; a working provider key (OpenAI, Groq, DeepSeek, OpenRouter, Together, or Gemini) is required for every generative operation. The raw key is never stored in plaintext and never re-sent to the client after saving (only provider, status, last 4 characters, and last-checked time).
- Every numeric relevance/similarity/confidence value shown must be a real value returned by the API or explicitly absent, never invented or displayed as a fabricated percentage. Confidence is always a band (high/medium/low), never a percentage.
- Every citation/reference string is deterministic (server-formatted), never LLM-generated; an unresolved citation reads "Not available," never a guess.
- Every RAG answer, gap, comparison cell, key point, and direction that makes a factual claim must be traceable to a real evidence span (quote plus section/page) or the claim is flagged unsupported.
- Cross-tenant access to any workspace-scoped resource reads as "not found," never as a permission error -- already enforced server-side; the frontend must not contradict it.
- Long-running operations (discovery, gap generation) are asynchronous (job-polling); chat streams over SSE; most other operations are synchronous.
- The backend API is fixed and already implemented (FastAPI, 14 phases already shipped and tested); this frontend consumes it as-is and does not require any new backend route beyond what already exists, except CORS enablement, which is pure infrastructure.
- No production code path may render fabricated or mock research results.

## Product Principles

1. Never show a number, citation, or claim the system cannot point to a real source for. If evidence is missing, say so.
2. Make the system's own reasoning inspectable, not just its output. Signal breakdowns, fired rules, evidence spans, and the activity log are first-class UI.
3. BYOK users are technically literate. Clarity over cuteness.
4. A workspace is the unit of work. Every synthesis feature is a lens on the same persistent paper collection, not a separate silo.
5. Degrade honestly. A missing LLM key, an unanswerable question, or an unresolved citation is a clearly labeled state.
